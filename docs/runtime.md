# Native runtime

Install `Domains/` as the native `Servers/Domains` extension. Run the native extension install/upgrade lifecycle before adding registrar accounts. Installation verifies every retained schema after migration; incomplete history or shape requires restoring the original database and migration history. Rollback and uninstall retain financial records, global reservations, templates and accounts. No automatic retained-data adoption or repair exists.

One boot authority registers the native financial guards, cart admission before invoice binding, authenticated routes, permissions, policies, both navigation collections, paid-invoice work and the minute scheduler. Generic server editing excludes encrypted settings; independent pre-mount/hydration guards refuse unsafe native editors when route caches are stale. Refresh route caches after installation. Disabling a native server pauses account processing; retained server identities cannot be repurposed or deleted. Legacy Enom processing must be paused before installation; it cannot be re-enabled while this runtime is installed. Returning authority to the legacy extension requires a separately reviewed migration.

Processing and optional customer reminder schedules default off. Registrar setup requires a current permission, one-use confirmation, reason and encrypted before/after audit. Enabling additionally requires a complete account-bound runtime composition, verified credentials, shared atomic cache/session storage and an asynchronous database/Redis queue with retry_after of at least 900 seconds. Run the worker with a timeout above 840 seconds and below retry_after; the unique tick times out at 840 seconds, operation jobs at 300 seconds. No real provider verifier, write acceptance or transport is installed by default. Provider and database concurrency acceptance remain deployment gates. Live-site confirmation currently requires the trusted AccountBindings integration; the staff activation form cannot provision live-site acceptance.

`RuntimePorts::register` attaches an independently reviewed factory to one immutable account fingerprint. It supplies acquisition, reconciliation, renewal execution/writer/completion and management engine/protocol objects. Every engine retains its funding, identity, generation, current ownership and uncertainty checks. Missing or incomplete factories cannot enable processing. `registerInitialManagedRecordObservations` is the single pending initial-observation producer attachment; without registration it is a tested no-op.

Run native queue workers and `schedule:run` on one shared deployment. The minute scheduler dispatches one unique runtime job. Account turns commit before bounded work; each minute handles at most eight accounts, with 25 requests, domains and TLDs per account. One observation/catalogue account turn runs per scheduler invocation to bound interruption and avoid advancing unattempted accounts. Observation, catalogue refresh, publication, renewal billing, transfer deadlines, automatic credits and reminder inspection each retain their own eligibility checks. Durable per-operation polling backs off pending/uncertain checks from five minutes to six hours; unfunded awaiting-payment or missing-code sweeps wait fifteen minutes; funded ready operations retry after one minute. Unique operation jobs bound backlog. Authority drift records a durable staff alert without adding failed jobs. Jobs carry only an operation locator and re-read authority. Unpaid acquisitions and missing transfer codes wait without being converted to permanent holds. Read-only observations and financial reconciliation continue with processing off when credentials remain readable. Physical reads, registrations/contact-profile writes, renewals and management exchanges share the same limiter. Acquisition and renewal reserve physical capacity before sealing; unsealed acquisition capacity refusals retain their original claim and retry at most five times inside the original five-minute execution window before a refundable hold. Expired or exhausted local claims require a refund rather than staff re-queue. Background wire starts stop at 48/minute, reserving 12 of the shared 60 for interactive work.

Registrar setup shows last completed turns, binding drift, saved wire usage and unresolved notification claims. Compare rotation lag with account count; inspect failed native queue jobs before retrying. An expired scheduler lock does not authorize an uncertain registrar write. Restore the original binding rather than rebind retained history. Notification check review records independent inspection; a continuing failure reopens the alert. Notification handoff review records independent staff inspection and never releases or resends the original claim. Render/check failures remain retryable before handoff; uncertain handoffs never replay automatically. Schedule audit segments rotate after 100 edits or before the encrypted text limit into encrypted native settings under the same account lock; retain previous application encryption keys until audited re-encryption.

Paid missing-code and actual account-credit notices work with optional schedules off. Native notification preferences and template/channel switches still apply. Queue acceptance is not delivery confirmation.

Themes can use the read-only `NativePresenter` singleton:

- `service($owner,$serviceId)` and `services($owner,$ids)` (maximum 250) return safe owned DTOs keyed by native service ID, requiring both native and ledger ownership.
- `invoice($owner,$invoiceId)` returns DTOs keyed by exact retained native invoice-item bindings; unrelated or transferred lines return no DTO.
- `checkout($owner,$cartItem)` returns canonical name, neutral registration/transfer label, term, holding-account annual renewal quote and a neutral owner/current-cart-scoped edit URL. Editing updates the existing native cart line through fresh admission rather than adding a duplicate. Missing quotes stay unavailable.

Advisory owner forms inspect at most 100 domain operations and 100 related payment rows; longer histories require staff review and expose no action. Mutation authority still checks complete locked history.

`OwnedDomain::renewalDue` is the pending issued renewal invoice’s due date; `expiry` remains the registrar-confirmed domain expiry. The `domains::checkout-line` and `domains::invoice-line` partials consume these projections. No-action held registrations display “Processing.” Customer actions can still require “Needs attention.”
