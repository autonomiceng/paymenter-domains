# Enom inbound transfer coverage

The deployment must set strict boolean `domains.enom_writes.transfer=true`, TEST identity mode and the TEST catalogue before boot. Registration, renewal and management remain independent. This composes the existing bounded transfer protocol, explicit TransferPrecheck/RDAP, accepted annual ending and registry policy, processing and fresh preflight USD balance checks. The factory performs no queries or transport work.

TEST accounts also need the **Transfers (experimental)** switch (`domains_enom_test_transfer`), which only gates new sends and new orders: work already sent keeps reconciling. With no saved `domains_transfer_endings`, What you sell decides which TLDs transfer. Catalogue acceptance reuses the audited encrypted route/interval record and annual transfer terms. Enabled deployments name TP_CreateOrder in that review. The owner signs in through native checkout, pays the native invoice and enters the code on the existing authenticated domain page before or after payment. No anonymous code storage is added. Code bytes remain encrypted, excluded from serialization and scrubbed from requests and session input.

Every physical TEST request counts against the per-login TEST send limit. Two fresh preflights precede the single TP_CreateOrder; it is counted right before send, after sealing, and never refunded. A refusal before send remains a proven-unsent hold. Release unsent hold retains its audit and requires fresh admission, current funding and a saved code before its deadline. Sealed refusal can reset only when the operation's own scope shows TP_CreateOrder was never sent. Audited Close and credit account also closes a retained proven-unsent cap hold after the code deadline, preserves validated refusal/terminal evidence and adds exactly one native account credit with zero provider calls. A lost reply is retained uncertainty, never a second transfer or automatic credit.

TransferOrderID is a transfer-status reference, never a billing OrderID. The existing operation state remains uncertain while the provider transfer is pending. Read-only status/history reconciliation requires the captured transfer reference, accepted action-specific history, a unique original charge, owned domain identity and expiry advanced by the full transfer year. RDAP unknown is advisory and retains its missing baseline; it cannot invent expiry proof or complete automatically. Genuine RDAP 404 and current creation/transfer locks refuse dispatch.

Installed socket-free fixtures exercise guest native-cart/login continuity and guest EPP POST refusal, paid/code timing, exact EPP bytes, current deployment revocation, pre-seal and sealed call refusals, audited capacity recovery, status/charge completion and duplicate turns, separate PHP restart, lost response, current RDAP refusals/unknown, timely contact correction with audited release, late correction without dispatch and runtime-driven idempotent 30-day missing-code credit, exact transfer-off checkout wording and cap-to-pending recovery. Owner and staff page views make zero provider calls. Native guards cover strict flags, identity/catalogue/binding, exact action/state scope and pure independent composition. Mutation checks run against these guards and the installed send/confirmation boundaries.

These are synthetic protocol fixtures. No real registrar or RDAP request is made, and no provider-supported TEST transfer fixture has been accepted. Actual-stack transfer acceptance remains open until such a fixture and an explicit request/spend budget are supplied. Production locking and visual acceptance require separate evidence.
Owner JSON code rejection scrubs the request and preserves saved transfer data; the contact-validation hold preserves encrypted payload bytes.

Live uses the same bounded protocol with its own strict `domains.enom_live.transfer` flag,
site/account binding, `domains_enom_live_transfer` route/fingerprint acceptance and Live call/spend
guard. The native socket-free Live regression checks default-off and strict flags, refusal of
settings-based activation, separation from TEST acceptance, What you sell fallback only after
acceptance and a saved list narrowing it, native funding/code, missing configuration/acceptance,
call/spend refusals before seal, one live-route TP_CreateOrder, original history/status/expiry
completion after opt-out and no replay on unknown status or duplicate completion. No public Live
activation or pilot switch is added. Activate remains unbuilt.
